# 项目报告

先确定报告面向谁、覆盖什么时间段。用户已经说明的范围直接采用。

1. 阅读任务提供的记录和项目文件。区分已经完成且有证据的成果、正在进行的工作、尚未执行的计划。
2. 需要历史上下文时使用当前可用的项目记忆或已注入上下文；不能读取的记录明确说明，不虚构数字和结论。
3. 参照 `assets/report-template.md` 组织报告，删除不适用的段落，不保留占位文字。
4. 将关键结论关联到具体文件、任务结果或来源。测试通过、部署完成、外部发送分别核对。
5. 用户要求文件时，将成品写入项目目录并检查实际内容；最终回复给出文件名和最重要的结果。

使用用户要求的语言。简短报告可以直接回复；未要求文件时不必制造额外文件。
