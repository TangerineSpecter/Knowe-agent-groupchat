# 单用户网页版实施与验证

## 范围

保留桌面端，复用聊天、审批、模型接入和 Agent 引擎；增加浏览器访问及单容器 Compose 部署。默认使用独立服务实例，桌面本地实例与 Web 实例不自动同步。第一版面向桌面浏览器，不实现操作系统通知或 Web Push。

## 实现边界

- `backend/web.py`：同源静态站点、单用户密码登录、HttpOnly 会话、来源检查、内部 HTTP/WebSocket 网关、上传与下载。
- `backend/web_workspaces.py`：Web 工作根目录、自动项目目录、真实路径校验；未设置 Web 工作根时沿用桌面端策略。
- `backend/web_state.py`：独立 SQLite 通知投影和会话撤销记录；通知不承担任务执行，不依赖浏览器在线。
- `backend/hub.py`：可选事件观察者，离线期间仍记录通知；桌面入口没有额外观察者。
- `src/shared/deployment.ts` 与 `runtimeEndpoints.ts`：按构建模式适配，桌面继续使用主进程提供的端点，Web 使用同源网关。
- `src/web`：登录前置、先读取服务器配置再挂载应用、目录浏览、通知中心。
- 现有文件预览器复用到 Web 新标签页；产出文件与上传附件均可下载。
- `Dockerfile.web`、`compose.yaml`、`deploy/install.sh`：单用户容器部署、非 root 默认运行、挂载持久目录、健康检查、优雅停止。

## 审视中修复的共享问题

1. 首次配置原来只更新 mainModel，同时发送空模型清单，后端池模式将其清空。首次保存现在同步建立主池条目。
2. 模型清单的公共快照原来未逐条脱敏，清单再次保存也没有正确保留已有凭据。现在逐条脱敏，并按模型身份和凭据范围保留服务端密钥。
3. 保存回执只能确认本次提交的配置，不能覆盖提交期间新输入的 Key；首次引导只保留一条测试→应用流程。
4. 主动断开原来仍可能安排自动重连；现在取消重连计时器并忽略旧连接事件。Web 登录过期停止重连，恢复网络或长时间离开后重新同步。
5. 目录恢复倒计时误把翻译函数传给 clearInterval，已改为实际计时器句柄。
6. 输入框占位提示原来捕获首次连接状态，已改为读取最新连接状态。
7. 补齐停止 Worker 的出站契约和已有活动校准的类型声明，清理严格类型检查发现的空值边界。
8. 服务端“审批永不超时”以 null 表示，原来刷新后被前端还原为 300 秒。现在正确还原为不限时，并验证修改语言后仍保持不限时。
9. 通知按审批卡身份去重，记录提前到达的审批结果，避免启动回放和实时事件交错时重新出现已结束审批。
10. 登录初始化失效后忽略迟到回执；异常的成功 HTTP 响应按错误处理；WebSocket 二进制帧不能绕过文本命令限制。

## 已执行的验证（2026-11-12）

- `npm run web:typecheck`：生产 Web 源码严格类型检查通过。单独排除历史测试夹具，不放宽 strict 配置。
- `npm run web:build`：通过；主应用仍有既有大分块提示。
- `npm run electron:build`：通过，包括内置主进程预览保护检查；不等同于安装包和原生桌面全流程验证。
- 单独执行 `tsc -p electron/tsconfig.json` 仍报告未修改的桌面文件中的既有问题：`will-frame-navigate` 事件声明及 updater 未使用常量；没有将它描述为全仓类型检查通过。
- 后端定向回归：50 项通过，覆盖网关、附件、持久化、项目 ID、模型配置以及真实引擎离线执行。
- 前端定向回归：34 项通过，包含真实 TCP WebSocket 的消息重放、心跳、乱序、主动断开及手动重连。
- 本机隔离实例：实际浏览器完成登录、首次模型测试与应用、自动目录建项目、刷新后读取服务器配置；未出现页面脚本错误。
- 实际浏览器完成文本、DOCX、Excel、PDF 预览，文件下载、HTML 沙箱、持久通知显示、附件上传及跨标签页退出登录。
- 离线测试：服务端 user_echo 确认后关闭所有 WebSocket，真实项目引擎继续产生回复与审批卡；重连回放恢复，两类事件均可见，通知未读记录仍存在。
- 模型验证使用本机模拟兼容接口与 fake 项目 Agent，没有使用用户真实 API Key 或真实模型费用。

## Docker 与 Compose 实测

磁盘空间问题由用户清理解决，复查 Docker 文件系统约有 4.2 GB 可用空间后，完整镜像已成功构建并导出为 `knowe-web:validation`。实测平台为本机 ARM64 Docker Desktop。镜像使用锁定版本及哈希的 Python 依赖，并包含 Node/npm、Git、中文字体和 Chromium 无头组件。ARM 实测补齐了 Playwright 驱动需要的 libatomic1。

多轮构建后磁盘曾再次耗尽；逐条核对 BuildKit 记录后，只回收本次 Knowe 构建的可重建缓存，保留最终镜像、现有容器与数据卷，复查约有 1.5 GB 可用。该机器的 Docker 虚拟磁盘总容量约 7.8 GB，持续开发构建的空间仍较紧张。

`scripts/verify-compose-web.py` 在独立 Compose 项目、临时挂载目录和本地模拟模型中完成以下验收，结束后删除自己的测试容器，不挂载已有用户数据：

- Compose 启动与健康检查，非 root 用户读写工作目录。
- 容器内实际执行 Python、Node、npm、Git；启动 Chromium 并渲染页面。
- 模型测试和配置应用，自动创建独立项目目录。
- 服务端确认消息后关闭全部 WebSocket，任务继续产生回复和审批；重新连接能回放。
- 强制重建应用容器后，登录、模型凭据、签名附件下载、Agent 回复和通知已读状态均保留。
- Chrome 实际完成登录、服务器已有目录选择、建项目、上传、通知中心、文件预览与下载、中英文切换、跨标签页退出。
- 更新语言时，“审批永不超时”仍保留；1024×768 下通知面板可访问。
- 安装脚本语法及隔离模拟检查通过；重复运行保留配置、密码和数据。root 执行首次安装时默认为容器 UID/GID 1000，仅调整本次新建目录和密码的所有者。

可复验命令见部署文档的“隔离验收”。浏览器截图和 Compose 日志默认输出到系统临时目录，测试不调用付费模型。

## 验证边界

- 尚未连接用户真实模型执行实际项目长任务；当前验收使用兼容接口模拟服务与确定性的项目 Agent。
- 容器重建证明持久数据可恢复，不代表任意正在执行的外部命令都能在进程重启后续跑。
- 未实测 x86_64、桌面安装包或公网 HTTPS 反向代理；部署文档提供配置要求。
- 第一版以桌面浏览器为目标；Web 新入口支持中英文，部分后端错误仍为中文。

部署操作见《网页版部署.md》。
