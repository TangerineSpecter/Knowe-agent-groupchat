# 单用户网页版部署

网页版与桌面端共用聊天、审批和 Agent 引擎。桌面端入口仍为 Electron；网页版入口为 `python -m backend.web`。网页与桌面默认运行独立实例，数据不自动同步。不要启动两个进程直接共享同一数据目录。

## Docker Compose

在项目根目录执行 `./deploy/install.sh`。需要 Docker Engine / Docker Desktop 和 Compose v2。脚本保留已有密码、数据和自定义配置，并将实际选用的端口、基础镜像和 npm 源保存到 `.env`。

宿主机默认端口为 **18090**，被占用时向后查找空闲端口，最多检查 100 个。脚本同时检查宿主机 TCP 监听和 Docker 已发布端口，并在镜像构建结束后再次检查。以脚本最终打印的地址为准；实际端口可用 `grep '^KNOWE_PORT=' .env` 查看。访问密码见 `deploy/web-password`，登录后在设置中配置模型。镜像默认使用真实 Agent，未配置模型前必须完成首次引导。

旧脚本生成的 8090 配置，如果还没有 Knowe 容器、也没有启动过 Web 实例，会自动迁移到 18090。已经运行的 Knowe 使用的端口会保留，不会被误判为其他服务占用。可以用 `KNOWE_PORT=28090 ./deploy/install.sh` 设置起始端口；冲突时仍会自动避让并保存结果。

默认只绑定服务器回环地址。远程使用可通过 SSH 转发 `ssh -L 18090:127.0.0.1:18090 user@server`，再打开 `http://127.0.0.1:18090`。如果脚本选择了其他服务器端口，将命令中第二个 18090 替换成实际端口。若要在可信局域网直接访问，在 `.env` 设置 `KNOWE_BIND_HOST=0.0.0.0`；HTTP 会明文传输密码，公共网络请使用 HTTPS 反向代理。

HTTPS 反向代理需要转发普通 HTTP 和 `/api/runtime/ws` WebSocket（包括 Upgrade/Connection），允许至少 65 MB 请求体，并延长 WebSocket 空闲超时。设置：

```dotenv
KNOWE_WEB_ORIGIN=https://knowe.example.com
KNOWE_WEB_SECURE_COOKIE=1
```

`KNOWE_WEB_ORIGIN` 必须精确匹配浏览器访问的来源（协议、域名、端口，不带路径）。网关不信任任意客户端提供的转发头。建议专用域名部署在 `/`，目前不支持子路径部署。

修改环境变量后运行 `docker compose up -d`。Compose 将实际宿主机端口映射到容器网关的 8090；运行时 HTTP、WebSocket 仅监听容器回环地址，内部令牌不返回浏览器。HTTPS 反向代理也应连接实际选用的宿主机端口。

## 目录与权限

| 宿主机默认目录 | 容器路径 | 用途 |
| --- | --- | --- |
| `deploy/data` | `/data` | 聊天、设置、Agent 内部状态、通知、持久签名密钥 |
| `deploy/workspaces` | `/workspace` | 项目文件、上传附件、用户缓存 |
| `deploy/web-password` | `/run/secrets/web_password` | 只读访问密码 |

新建项目默认创建 `/workspace/projects/<项目ID>`，也可选择工作根目录内已有文件夹。上传附件存放于 `/workspace/uploads`。路径持久化采用容器路径，迁移服务器时保留相同的容器挂载点。

`.env` 可设置 `KNOWE_DATA_PATH`、`KNOWE_WORKSPACE_PATH`、`KNOWE_PASSWORD_PATH`。宿主机目录须允许 `KNOWE_UID:KNOWE_GID` 读写；安装脚本默认使用执行者 UID/GID，root 首次安装和手动部署默认 1000:1000。root 安装只调整本次新建默认目录和密码文件的所有者；已有目录、自定义挂载及已有密码需要自行确认权限。镜像以普通用户运行，临时安装系统软件请修改镜像，不要在运行容器中用 root 临时修补。

基础镜像包含 Python、Node/npm、Git、Chromium、中文字体和附件文本提取依赖。项目依赖在容器中安装，避免直接复用宿主机虚拟环境或 node_modules。Agent 与服务处在同一容器、同一用户权限下；这是个人可信执行环境，不是恶意代码沙箱。不要挂载 Docker socket 或整个宿主机文件系统。

## 任务、通知与恢复

浏览器刷新、关闭、客户端休眠不会主动停止服务器已接收的任务。重连后通过现有消息回放和状态快照恢复；待审批任务按服务端配置等待或超时。发送但没有服务端确认的消息不能视作已接收。

通知中心记录审批、终态任务和异常，读状态存服务端。页面打开/恢复时汇总未读数量，不提供操作系统通知或关闭网页后的 Web Push。

容器重启属于执行进程重启，不能承诺每个外部命令无缝续跑。部署更新前先查看活动任务，等待结束或明确停止。重新打开后核对任务状态，不要盲目重发有副作用的操作。

## 更新、备份与排障

- 更新源码后：`git pull --ff-only && ./deploy/install.sh`。安装脚本会复用本地已有基础镜像、已选源及端口，并保留密码和数据。
- 查看日志：`docker compose logs --tail=100 -f knowe`。
- 查看健康：`docker compose ps`；HTTP 探针为 `/healthz`，不含用户数据。
- 停止：`docker compose down`（不会删除宿主机挂载目录）。
- 一致性备份：先停止容器，再备份数据目录、工作目录及密码文件。仅备份聊天数据无法恢复项目文件，丢失附件签名密钥会影响历史附件验证。
- 回退：保留上一版镜像和升级前的数据备份；数据迁移后不要直接让旧版程序读取新格式。
- 密码重置：修改密码文件，重建容器；旧登录会话失效。
- 网关无法启动：检查密码至少 12 字符、目录权限及容器日志。

## 本地开发

```sh
uv pip install --python .venv/bin/python -r backend/requirements-web.txt -r backend/requirements-dev.txt
npm ci
npm run web:build
# 另建仅本机可读的密码文件，再设置 KNOWE_WEB_PASSWORD_FILE；不要将密码写入命令历史。
PYTHONPATH=backend KNOWE_WEB_PASSWORD_FILE=/path/to/password .venv/bin/python -m backend.web
```

热更新前端使用 `npm run web:dev`，后端仍运行在 8090。Vite 代理 `/api` 到网关，浏览器访问 Vite 地址。生产使用构建后的静态文件，不运行 Vite 开发服务器。

## 隔离验收

在项目根目录、已安装上述 Python 开发依赖的环境执行：

```sh
docker build -f Dockerfile.web -t knowe-web:validation .
.venv/bin/python scripts/verify-compose-web.py
```

脚本创建独立 Compose 项目、随机密码、临时数据和模拟模型服务；实测离线执行、回放、非 root 工具运行和容器重建后的数据保留。结束后清理自己的测试容器，不读取正式实例数据或模型凭据，也不调用付费模型。日志默认保存到 `/tmp/knowe-compose-browser`（其他系统使用系统临时目录）。

增加真实浏览器 UI 验证：先执行 `.venv/bin/python -m playwright install chromium`，再给验收命令加 `--browser`。也可使用已有 Chrome，例如 macOS：

```sh
.venv/bin/python scripts/verify-compose-web.py \
  --browser-path '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'
```

UI 验证包括登录、目录选择、上传、预览下载、通知、中英文和跨标签页退出；截图输出到同一临时目录。`--image` 可指定其他已构建镜像，`--artifacts-dir` 可指定日志和截图目录。

## 构建资源与镜像源

镜像包含 Chromium 与项目执行环境，建议至少预留 4 GB 内存及 10 GB 可用 Docker 磁盘空间；构建缓存会额外占用空间。Python 部署依赖由 `backend/requirements-web.lock` 固定版本和哈希，修改 `requirements-web.txt` 后需重新生成锁文件并验证。

安装脚本实际拉取 Node、Python 基础镜像，而不是只探测仓库首页。默认先用 Docker Hub，失败或单次拉取超过 **60 秒**后改用 [DaoCloud 镜像服务](https://github.com/DaoCloud/public-image-mirror)。本地已有的镜像直接复用；成功选择的镜像地址会保存，后续安装优先复用。采用 DaoCloud 时，未自定义的 npm 源同步设为 `https://registry.npmmirror.com`。

可在 `.env` 中调整：

```dotenv
# auto：官方优先，失败切换；mirror：镜像源优先；official：只用官方基础镜像
KNOWE_DOWNLOAD_SOURCE=auto
# 每次基础镜像拉取的最长秒数，慢链路可调大，范围 1–3600
KNOWE_PULL_TIMEOUT=60
```

也可以直接执行 `KNOWE_DOWNLOAD_SOURCE=mirror ./deploy/install.sh` 跳过先试官方源的等待。自定义 `KNOWE_NODE_IMAGE`、`KNOWE_PYTHON_IMAGE`、`KNOWE_NPM_REGISTRY` 会保留，私有仓库不会被替换成其他仓库。官方和镜像服务都失败时，脚本停止并提示，不会继续启动服务。

日志分成基础镜像、应用构建、启动检查三个阶段，构建使用完整文本日志。npm 锁文件完整性、Python 锁文件哈希及 TLS 校验仍然保留；脚本不修改 Docker 全局配置或重启 Docker。
